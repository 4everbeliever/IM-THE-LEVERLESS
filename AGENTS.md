# Toolshed Rentals

React + Vite + Tailwind CSS project running inside Figma Make.

## Development Server

A Vite development server is **already running** on `$PORT` (default 8443). You don't need to start it manually.

- Preview URL: The user can access the running app through the preview panel
- Hot reload: Changes to source files are reflected immediately

## Project Structure

This is the canonical project structure. Start with task-relevant files below. Only follow imports or inspect other files when required, when a documented path is missing, or when the repository contradicts this guide.

- `src/main.tsx` - React entrypoint; imports `src/index.css` and mounts `src/App.tsx` into the `#root` element
- `src/App.tsx` - Primary application component and the usual starting point for UI work
- `src/index.css` - Global CSS entrypoint and Tailwind CSS v4 import
- `index.html` - Vite HTML shell containing the `#root` element and loading `src/main.tsx`
- `package.json` - Project dependencies and the Vite build, development, preview, and formatting scripts
- `vite.config.ts` - Vite configuration with React, Tailwind CSS v4, and Figma Make plugins plus the `@` alias for `src`
- `.mise.toml` - Toolchain versions for Node.js and pnpm

## Toolshed Rentals app

Tool and equipment rental app for branches in Bohol (Tagbilaran, Panglao, Tubigon). Backend is Supabase project `ophgpdwzoeuheshcfrrc`.

Routing is in `src/App.tsx` (`createBrowserRouter`, mounted by `src/main.tsx`):
- `/` redirects to `/dashboard` or `/login`
- `/login` public sign-in
- `/dashboard` any signed-in user, guarded by `ProtectedRoute`
- `*` NotFound

Key files:
- `src/pages/Dashboard.tsx` - the signed-in app shell (sidebar, header, inventory, bookings, maintenance, add item, admin Users page, booking and payment modals) wired to real Supabase tables via TanStack Query.
- `src/hooks/useAuth.ts` - session via TanStack Query
- `src/hooks/useProfile.ts` - current user's profile and role
- `src/hooks/useAdminUsers.ts` - admin-only user list and role changes
- `src/hooks/useInventory.ts` - items and branches queries and add-item mutation
- `src/hooks/useBookings.ts` - bookings query, create booking, check-out, and return mutations
- `src/hooks/usePayments.ts` - record payment mutation
- `src/hooks/useMaintenance.ts` - maintenance logs query and create log mutation
- `src/lib/supabase.ts` - Supabase client (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`)
- `src/index.css` - the whole design system (plain CSS classes such as `.card`, `.button`, `.badge`, `.table-card`). Reuse these classes. Do not restyle.
- `supabase/migrations/` - SQL migrations (`0001_profiles_and_roles.sql`, `0002_rental_schema.sql`), run in order in the Supabase SQL editor
- `supabase/functions/server/` - Hono Edge Function (health check only so far). `kv_store.tsx` is autogenerated, do not edit.
- `utils/supabase/info.tsx` - autogenerated, do not edit

## Roles and security rules

Roles: `customer` (default for every signup), `staff`, `admin`. Stored in `public.profiles.role`.

| Role | Can do |
|---|---|
| customer | Browse items, book, see own bookings |
| staff | Everything a customer can, plus all bookings, maintenance logs, add items |
| admin | Everything staff can, plus the **Users & roles** page |

- The first admin is set by hand in the SQL editor: `update public.profiles set role = 'admin' where email = 'you@email.com';`
- Admins get a Customer / Staff / Admin preview toggle in the header. It only changes the view, never real permissions.
- **UI checks are not security.** Real enforcement is Row Level Security in `supabase/migrations/0001_profiles_and_roles.sql`. Users read only their own profile; admins read all and change roles; nobody changes their own role.
- SQL helpers for policies: `public.is_admin()`, `public.is_staff()` (staff or admin), `public.current_app_role()`.
- Every new table needs RLS enabled and explicit policies. Never rely on the UI to hide data.
- The anon key ships to the browser, so treat it as public. Never put the `service_role` key in a `VITE_` variable. It belongs only in Edge Function secrets.
- Edge Function routes that do privileged work must verify the caller's JWT and role. Do not leave `origin: "*"` CORS on those routes.

## Styling

This project uses **Tailwind CSS v4** through the `@tailwindcss/vite` plugin configured in `vite.config.ts`. `src/index.css` imports Tailwind with `@import 'tailwindcss';`. Use Tailwind utility classes directly in JSX and put global CSS or Tailwind v4 theme customization in `src/index.css`. This scaffold does not need a Tailwind config file or PostCSS config.

`src/main.tsx` imports `src/index.css`, so global font wiring belongs in `src/index.css`. Keep CSS `@import` statements first, then add any `@font-face` rules and font-family defaults there.
